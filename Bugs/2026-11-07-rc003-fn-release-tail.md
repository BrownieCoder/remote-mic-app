# 小米 2 Pro 按住说话，松开时偶尔漏掉句尾

2026-11-07，候选修复。小米蓝牙遥控器 2 Pro（RC003，固件 2671），macOS 26.0.1，SayAll 1.9.21 (174)，豆包输入法 1.0.3，音频输出 MiRemoteV 2ch。使用 Fn 按住说话，未开 Fn 点按。

**观察。** 说完立即松手，有时最后几个字没有上屏，下一次只能单独补说。两次人声复测的“一二三，测试结束”都完整，不能当成稳定复现。把声音换成开头和结尾都有标志词的固定语料，让同一只遥控器负责真实按压，音频经过同一个虚拟麦克风送给豆包：保留开头、但按原提示松手时，豆包停止读取比播放完成早 1.212 秒，末词“上海”没上屏。等到播完再松手的一轮，首尾词都上屏。三轮有效对照另有一次按早重试。

**对照日常直通。** 排除上述固定语料实验后，118 次遥控器会话有 117 次能与豆包的系统采集开始、停止记录唯一配对。其中一次，系统通知豆包已停止采集后约 483 毫秒，SayAll 才报告最后一批音频播完；从最后一次蓝牙收包计时推算，停止采集后约 422 毫秒还有数据抵达。当次尾部采样非零。其余 116 次的采集停止通知都晚于播完。118 次停止时都没有残缺蓝牙分片。这些计时没有记录用户的语音或文字，也无法指出那一次是否真的漏词，或是哪个动作让豆包停止。

**代码与设备。** 原版由 macOS 把小米的 F5 映射为 Fn。SayAll 的音频可以继续排空，但它不拥有这一个 Fn 的松键动作。固定延长空播放或给所有快捷键加一个等候时间，都解决不了这个归属问题。实机的事件服务和 HID 设备位置编号不相等；在系统注册表的直接祖先链上，事件服务经过一个 HID 接口可对应到这只小米的确切设备。不能把相同型号编号当作同一台设备。

**软件按住 Fn 的对照。** 在豆包的临时输入框中用同一段固定语料测试，只改变 Fn 松开的时刻。有实际播放积压时，首个有效配对中，播完前 1.59 秒松开没有末词“上海”；播完后 7 毫秒松开，首词和末词都出现，末词只有一次。无额外积压的对照，两种松法都保住末词。这可以验证豆包的行为，不能代替实体遥控器按下到首字的测量。

**两句之间的异常。** 播放器卡住时，光抬起 Fn 还不够。以真实 MiRemoteV 输出暂停播放、触发超时、立即开始下一句，原先排队的 2,880 个样本会在下一句的收音窗口播出。为此让托管的遥控器声音使用同一引擎里的独立播放器：正常松手时让本句播完，异常恢复时只作废这一路的旧声音。复测同时保留另一音源，从混音端检查新句和未受影响的声音。

**验证边界。** 目标是把 Mac 已收到、属于这一句的音频送完，并验证输入框的最终末词。遥控器没传出来的声音无法补回。还须分别核实软件 Fn 对豆包的实际作用、两句快速重按是否各自提交、权限或输出丢失后的清理，以及正常路径有没有变慢。首词和输入法冷启动另行处理。

候选在单台 RC003 上提供本次连接可选的“播完尾音再松开 Fn”。默认仍用原硬件映射；如何比较和回退见[语音键手册](../Testing/VoiceKeyModes.md)。
